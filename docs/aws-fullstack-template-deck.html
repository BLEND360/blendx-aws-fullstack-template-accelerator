Stack Selection

Every choice is already proven in the MVP

Nothing on this list is new to Blend. Each layer runs in production today in blendx-aws-mvp-be / -fe, so the choices are an inheritance with reasons, not a bet.

BackendPython 3.12 · FastAPI · uvNative async is a prerequisite for streaming a harness response; uv gives a locked, reproducible build

Out of v1 on purpose: relational DB, custom domains, WAF, autoscaling, and the rest of the AgentCore surface (gateways, MCP runtimes, knowledge bases). A harness definition is eight lines of JSON, so it ships. The surface around it is six CDK stacks and five workflows in the MVP, so it waits (ST-13).

Core Deliverable

The harness integration layer

This is the part of the MVP most worth extracting, and it's not a thin wrapper: ~1,200 lines across four files. It defines how custom business logic invokes a harness and streams the result to a browser. The browser sends only { "message": "..." }.

The hard parts, already solved in the MVP

  • The blocking SDK iterator is bridged to an async generator, with the request id re-bound inside the worker thread
  • A read timeout tells a slow turn apart from a wedged one
  • Protocol sentinels are filtered with lookbehind, because a sentinel can arrive split across two chunks
  • An unknown or failing tool becomes a tool result sent to the model instead of an exception that ends the turn

Decisions · Next Steps

What we need to start

One decision blocks work, and it isn't needed until Sprint 2. The rest can be settled during implementation.

Blocking
Does the template create a VPC or import one?
A team with no VPC can't deploy today. Proposed: create a minimal VPC by default, with an import-by-id override. Needed before Sprint 2 (ST-07.1, ST-14).
Open
Is SAML federation on by default?
Proposed: native Cognito users by default, and SAML behind a flag driven by a metadata file.
Open
How do clones get fixes?
A GitHub template repo gives no upgrade path. Accept that for v1 and track it for v2.
Resolved
Which harness does a new project use?
Its own starter harness; harness.arn + endpoint override it.
Resolved
Our own CDK stack, or the agentcore CLI for the harness?
The platform's CLI and naming convention, which keeps a template-born harness promotable to the Hub.
Not v1
Register template harnesses in the Hub catalog?
Today that means SQL writes through a bastion, which a clone must not do. Revisit when blendx-aws-foundry-be exposes a write API.
Recommendation
START: SPRINT 25 Approve the scope and the two-sprint plan, and settle the VPC decision before Sprint 26. The work is extraction of code that already runs, so the risk sits in deploy-time behavior, and that's what the buffer and the cut line (ST-12 → ST-13 → ST-11) are for. Core isn't negotiable: without it the template doesn't run end to end, and running end to end is the deliverable.
